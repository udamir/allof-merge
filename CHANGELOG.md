# Changelog

## 1.0.0 (unreleased)

A redesign of the merge engine behind the same public API (`merge`, `allOfResolverHook`, the rule sets and every utility export of 0.6.8 keep their signatures; nothing was removed). Based on the audit in `docs/ANALYSIS.md` (findings AM-01 … AM-27), the design in `docs/DESIGN_PROPOSALS.md` and the verification in `docs/VERIFICATION.md` (findings VR-01 … VR-51, decisions D-1 … D-27) and the feature design in `docs/FEATURE_DESIGN.md` (AsyncAPI, `refAnnotations`, simplifications, property-based test); `test/audit` is the acceptance suite.

### Dependencies

- Requires `json-crawl` 1.0.0 (was `^0.5.3`). json-crawl 1.0.0 is not published to npm yet: `package.json` points at `vendor/json-crawl-1.0.0.tgz`, a tarball packed from the json-crawl 1.0.0 checkout (`json-crawl-fix`); switch the dependency to `^1.0.0` and drop `vendor/` once the release is out (release blocker VR-50). The bundles (`dist/index.cjs`, `dist/index.mjs`, `dist/allof-merge.min.js`) inline json-crawl, so at runtime they do not load the consumer's copy; the `.d.ts` files import types from `json-crawl` and need the 1.0 typings.
- json-crawl 1.0 renames the clone option `unsafe: true` to `circular: false` (the merge passes it; a raw-hook user must pass it too, see the README) and writes prefix rules as `"/<prefix>*"` instead of the 0.6 `"/^"` prefix map (custom vendor rules: `{ "/x-*": rule }`). It types the hook context `key` as `string | number | undefined` (`undefined` for the root): the clone hook writes the root through `cloneKey(key)` (`JSON_ROOT_KEY`, `"#"`). Lazy (parent-linked) paths keep deep documents linear (VR-04: depth 20 000 went from an out-of-memory crash to ≈ 0.1 s). Holes of a sparse input array stay holes in the output (the JSON serialization is the same, `null`).

- TypeScript target ES2018 (was ES6): object spread and rest compile to native syntax instead of `Object.assign`/`__rest` helpers, which called the `__proto__` setter on user keys (VR-21). The engine itself writes every user key through own-property-safe helpers (`src/safe.ts`), so the bundles are safe whatever the target.
- `package.json` version 1.0.0 (the bundle banner was still v0.6.8, VR-50).

### Output-contract changes (`docs/DESIGN_PROPOSALS.md` §5, `docs/VERIFICATION.md` §7)

- Two different `format`s in one conjunction are a contradiction (`false`, reported as `unsatisfiable` with `reason: "format"`), also overlapping and unknown pairs; the OpenAPI numeric lattice (`int32 ∧ int64` → `int32`, `float ∧ double` → `float`) is unchanged (user decision Q1 of `docs/NORMALIZATION_DESIGN.md` §9, replaces D-2, which kept the formats as `allOf` parts). `format` constrains strings only, so for a format-asserting validator the result rejects non-string instances the input accepts when no `type` excludes them.
- A lone malformed value of a validated keyword is dropped and reported (`{ allOf: [{ required: true }, { type: object }] }` → `{ type: object }`, was copied silently; Q9).
- A single-item `allOf` gets the simplifications of a merged node (F-10): `{ allOf: [{ anyOf: [A, A, B] }] }` → `{ anyOf: [A, B] }`, `{ allOf: [{ oneOf: [false, B] }, {}] }` → `{ oneOf: [B] }`, so `merge(merge(x))` equals `merge(x)`.
- `merge` without `rules` follows the document's `$schema` (draft-04 / 06 / 07, 2019-09 and 2020-12 → the 2020-12 rules; draft-06 when absent or unknown) and an OpenAPI 3.1 `jsonSchemaDialect`; OpenAPI versions are matched exactly (`"3.0"`, `"3.0.x"`, `"3.1.x"` and later 3.x; `"13.0"` is no longer OpenAPI). A 2020-12 document's array `items` is therefore kept as a fragment instead of being merged as a draft-06 tuple.
- Outputs of one merger share the copies of subtrees that need no merging between calls, and a repeated fragment-mode call (`merger.merge(node, { source })`) returns the result of the first call; as before, do not mutate results of a reused merger or use `freezeOutput`.

- A contradictory conjunction (`type: string ∧ type: number`, disjoint `enum`, different `const`, `allOf` containing `false`) is written as the boolean schema `false` instead of dropping the keyword or producing `undefined`/`null`; a property with an impossible schema stays in `properties` as `false`. The new option `unsatisfiable: "not-empty"` writes `{ not: {} }` instead (for draft-04 consumers). `onMergeError` keeps firing (AM-01, AM-05, AM-08, AM-09).
- An impossible `oneOf`/`anyOf` branch is removed (new option `dropFalseBranches`, default `true`; FEATURE_DESIGN decision Q3-1). This replaces the contract of earlier 1.0.0 drafts, which kept the branch in the array as `false` (AM-08; still available with `dropFalseBranches: false`). When every branch is impossible the node is a contradiction (`false`, `{ not: {} }`, or `{ allOf: [false], $defs: … }` with container siblings), reported once at the combinary's path; an impossible branch alone is not reported, nor is a combinary that was already impossible in the input (VR-41). `{ oneOf: [{ allOf: [string, number] }, number] }` → `{ oneOf: [number] }` (was `{ oneOf: [false, number] }`); `{ anyOf: [{ allOf: [string, number] }] }` → `false`. A `$ref` into a branch whose index shifts links the branch at its new index (D-27): `{ $ref: "#/definitions/X/oneOf/2" }` with `X.oneOf = [<impossible>, { type: integer }, { type: boolean }]` → `{ $ref: "#/definitions/X/oneOf/1" }` (also below the branch, through nested lists, and for `anyOf` duplicates removed by `dedupeAnyOf`, which link the equal branch kept); a pointer to a removed impossible branch stays a copy (`false`). An earlier 1.0.0 draft copied every pointer into a shifted branch.
- Always-safe simplifications on by default (each its own option, FEATURE_DESIGN §3, decision Q3-1): identical `anyOf` branches are kept once (`dedupeAnyOf`; never `oneOf` branches: `oneOf [A, A, B]` means `¬A ∧ B`), identical `allOf` parts kept next to the merged keywords are kept once (`dedupeFragments`: `allOf: [{ contains: N }, { contains: S }, { contains: N }]` → two fragments), identical (order-sensitive) `oneOf`/`anyOf` groups of different items are combined once before the cartesian product (`dedupeCombinaryGroups`: three copies of `{ oneOf: [string, number, boolean] }` give 3 branches instead of 27, six copies of a 4-branch group merge instead of exceeding `branchBudget`).
- `enum` and `required` keep the first-seen order and are de-duplicated instead of being sorted (AM-26).
- Two or more `pattern`s are conjoined as `^(?=[\s\S]*?(?:p1))(?=[\s\S]*?(?:p2))[\s\S]*$` (the previous `(?=p1)(?=p2)` rejected valid strings); patterns with backreferences or named groups are kept as `allOf: [{ pattern }, …]` fragments (AM-03).
- A broken `$ref` inside `allOf` leaves the node's siblings (such as a root `definitions`) in place; resolvable items are still resolved, the broken ones stay `{ $ref }` and `onRefResolveError` is called (AM-15).
- `integer ∧ number` is `integer` (AM-02); `contains: A ∧ contains: B` is kept as `allOf: [{ contains: A }, { contains: B }]` because it has no single-keyword form (AM-12); `nullable: false ∧ true` is `false` under the JSON Schema and OpenAPI rules (AM-11).
- The output is never a cyclic JavaScript object (D-4, D-4b; changes AM-24, where 0.6.8 and earlier 1.0.0 drafts produced a cyclic object for a cyclic `$ref`): every cycle re-entry is written as `{ $ref: "#<pointer>" }` to the source location of the node where the cycle started (the unmerged original, semantically equal), for whole-document merges, fragment merges with `source` (VR-30) and `mergeRefSibling` (#208 part b, VR-31) alike; cyclic JavaScript input is handled the same way, a cyclic value outside `source` becomes `{}` with `onMergeError`. The output is always JSON-serializable, and consumers that guard against cycles by `$ref` path (api-smart-diff) work unchanged.
- Repeated `$ref` targets and repeated conjunctions of the same items share their merged output instance, within one result and across the calls of one `createMerger` (AM-27, D-11, VR-25); `freezeOutput: true` deep-freezes the result for consumers that must not be able to corrupt shared instances.
- OpenAPI 3.0 `nullable` follows the 3.0.3 wording (D-1, VR-13, VR-14): an item with a `type` and without `nullable: true` forbids `null`, an item without `type` does not restrict it; `{type: string, nullable: true} ∧ {type: string}` → `{type: string}` (0.6.8: nullable). The idiom `allOf: [{ $ref: Base }], nullable: true` no longer yields a nullable schema when `Base` has a `type`. Two nullable items with conflicting types leave only `null`: `{ type: T, nullable: true, enum: [null] }`.
- Differing `format`s are kept as `allOf: [{ format: a }, { format: b }]` and reported (D-2, VR-16; 0.6.8: last wins). Only the OpenAPI rule sets (`openApiMergeRules`, `openApiJsonSchemaMergeRules`, 3.0 and 3.1) narrow `int32 ∧ int64` → `int32` and `float ∧ double` → `float` (D-14); the JSON Schema and GraphApi rule sets treat these pairs as conflicts as well (earlier 1.0.0 drafts applied the lattice everywhere).
- Tuple keywords are read per draft (D-18): under draft-04/06/07 rules (incl. the default draft-06 and OpenAPI 3.0) an array `items` (+ `additionalItems`) is the tuple and `prefixItems` is an unknown keyword (last-wins, earlier 1.0.0 drafts merged it as a tuple under draft-06/07 too); under 2020-12 rules (and OpenAPI 3.1) `prefixItems` (+ `items` schema) is the tuple and an array-valued `items` that has to be combined with other array shapes is kept as an `allOf` fragment `{ items, additionalItems? }` with `onMergeError`, a stray `additionalItems` is last-wins. `{ prefixItems: [string] } ∧ { items: [{ minLength: 1 }, number] }` → draft-06: both keywords side by side; 2020-12: `{ prefixItems: [string], allOf: [{ items: [...] }] }`.
- Links stay links (D-22, D-23): in a whole-document merge every `$ref` that resolves in the input still resolves in the output and keeps its meaning. A `$ref` (bare or with siblings) whose pointer runs through a node the merge rewrites (a node with its own `allOf`; with `mergeRefSibling` a `$ref` with siblings, with `mergeCombinarySibling` a `oneOf`/`anyOf` with siblings) is rewritten to the matching merged location when the value there is structurally equal to the original target merged on its own (`#/components/schemas/Pet/allOf/1/properties/id` → `#/components/schemas/Pet/properties/id`, siblings kept), and replaced by a copy of the original target otherwise (the merged location is stricter, or gone: a contradiction `false`, siblings distributed into `oneOf` branches). Siblings of a copied `$ref` are conjoined with the copy in every draft (D-24, see below; an earlier 1.0.0 draft dropped the constraint siblings under draft-04/06/07 / OpenAPI 3.0 / GraphApi rules and reported them with `refSiblingDropped`, which no longer exists). Cycle re-entries whose source pointer runs through a rewritten node point to the output location of the re-entered node, so such nodes are merged now: `Node = { allOf: [{ properties: { child: { $ref: "#/definitions/Node/allOf/0" } } }, …] }` was kept unmerged (D-17) and is merged, its `child` becomes a copy of the member re-entering itself. Fragment merges (`source` given) leave every `$ref` as it is: it resolves against the unchanged `source` (the D-16/D-21 inlining no longer applies there). The D-17 keep-unmerged re-merge remains only as a fallback for `$ref`s that can be neither linked nor copied (kept by a limit, outside schema locations, inside the siblings of a link). The raw clone hook rewrites links when the root is finished, without the fallback.
- Changed expectations against the D-16 / D-17 / D-20 / D-21 behaviour of earlier 1.0.0 drafts: a pointer into an `allOf` member or a sibling member whose merged value is equal is a link instead of a copy (`{ $ref: "#/allOf/0/properties/a" }` → `{ $ref: "#/properties/a" }`); a `$ref` with siblings through a merged node is linked or copied instead of keeping the node unmerged; cycles through `allOf` members no longer keep the `allOf`. Pointers written by the merge keep `$ & + , ; = : @` literal (`#/$defs/A`, was `#/%24defs/A`).
- `$ref` siblings apply in every draft (D-24, author intent): the siblings of a `$ref` are conjoined with its target under every rule set, also under draft-04/06/07, OpenAPI 3.0 and GraphApi rules, whose validators ignore every sibling of `$ref`. This is an intentional deviation from those drafts, documented in the README: `{ definitions: { Name: { type: string } }, allOf: [{ $ref: "#/definitions/Name", maxLength: 3 }, { minLength: 1 }] }` → `{ type: string, minLength: 1, maxLength: 3 }` (a draft-07 validator accepts `"abcd"` for the input). It covers a `$ref` allOf item with siblings, a node with both `$ref` and `allOf`, `mergeRefSibling`, and the copies of the link rules (which no longer drop constraint siblings). Found by the fuzz corpus replay (known issue KI-1, now a documented test).
- Fragment mode leaves `$ref`s as they are and a pointer through a `$ref` member links to the target's own location (D-25), e.g. `#/components/schemas/Pet/allOf/0/properties/id` with `allOf/0: { $ref: Base }` → `#/components/schemas/Base/properties/id`.
- Unknown and vendor keywords stay a silent last-wins by default (D-19, VR-43); a rule set without a `"/?"` fallback no longer throws `Merge rule not found` for an unknown key (0.6.8 carry-over) but falls back to last-wins as well. A key without a rule in the rule set (for example `prefixItems` under draft-07, `contains` under draft-04) is no longer part of its keyword group, so it does not hand the group's other keys back to the per-key table.
- `patternProperties × additionalProperties` (D-5, VR-10, VR-11): another item's `additionalProperties` schema is conjoined into the kept patterns when that item has no patterns of its own; identical patterns merge; every other interaction keeps the object shapes as `allOf` fragments (no synthesized lookahead patterns). Property names are matched against foreign patterns only within the `matchPatterns` limits and never for patterns with nested quantifiers (D-3, VR-02); otherwise the shapes are kept as fragments.
- Items carrying their own `unevaluatedProperties`/`unevaluatedItems` stay separate `allOf` fragments (a `$ref` item stays `{ $ref }`), the node's own `unevaluated*` is merged (D-8, VR-12).
- A contradiction next to container siblings keeps them: `{ allOf: [false], definitions/$defs/components/$id/… }` (D-10, VR-32).
- With `mergeRefSibling`, a broken or external `$ref` with siblings is left as it is; `onRefResolveError` only for broken local refs (D-9, VR-35).
- Identity keywords (`$id`, `id`, `$anchor`, `$dynamicAnchor`, `$schema`, `$vocabulary`) of `$ref`-inlined items are no longer copied into the merged node, so the output has no duplicate ids/anchors; the node's own identity keywords stay.
- `multipleOf` values whose least common multiple cannot be computed exactly (non-finite, subnormal, overflowing, beyond 2^53 or a 1e15 decimal multiplier) are kept as `allOf` fragments instead of hanging or returning `NaN` (VR-01).
- A missing `minContains` next to an equal `contains` counts as 1 (VR-15).
- Malformed keyword values (`required: true|null`, `enum: null`, `anyOf: true|{}`, `not: null`, non-array `allOf`, non-object `allOf` items, `type: []`, …) are ignored, the valid parts are merged and `onMergeError` is called; the merge never throws on them (D-6, VR-37, VR-42).
- Limits (D-7): a node exceeding `branchBudget`, `maxRefExpansion`, `expansionBudget` or `maxDepth` is left unmerged (keeping its `allOf`/`$ref`) and `onMergeError` is called; the output is always equivalent.
- `onMergeError` is no longer called for a `oneOf`/`anyOf` that was already unsatisfiable in the input (VR-41).
- A merger's options (`refAnnotations`, the simplification options) are fixed for its lifetime, so its memo never mixes results of different settings; a consumer that caches mergers per rule set must add these options to its cache key (api-smart-diff-redesign: `ruleSetId|mergeRefSibling|mergeCombinarySibling` → plus `refAnnotations` and the simplification options it sets).

### Fixed

- The D-17 fallback (a whole-document merge that re-merges with nodes kept unmerged) reported its limit twice through `onMergeError` (once per round); every report is now delivered once per merge, whichever round raised it.
- Per-key resolvers reported malformed values and kept parts with the generic "Could not merge values" message (`required: true` next to `required: [a]`, a legacy 2020-12 tuple handed back to the per-key table): they now report the specific message ("Malformed required value is ignored"), and the nested merge of `jsonSchemaMergeResolver` forwards its issues unchanged.
- Reporting was not repeatable across calls of one merger: a memoized conjunction reused by a later call (or the same node merged again) was silent. Issues are recorded with the output that raised them and replayed on every reuse.

- One input instance used at locations with different rules (a YAML alias, or a JS-built OpenAPI document using the same object under `info.x-…` and under `components/schemas`; the same object as an Avro and an AsyncAPI payload) was cloned once and the first output reused for both: it stayed unmerged under `components/schemas` or was merged under `info`, depending on the order. The identity memo of a merge call and the container-output cache are now keyed by the node's rules as well; sharing under the same rules is unchanged.
- `properties × patternProperties × additionalProperties` are merged together: a property is kept when it matches a pattern of another item or when that item has no `additionalProperties: false`, and the matching pattern schemas are applied to it (AM-04).
- `items × additionalItems × prefixItems` are merged together, including a single `additionalItems` meeting an `items` schema (AM-19); a conflicting or empty tuple position is `false` or `{}`, never `null` (AM-09).
- draft-04 / OpenAPI 3.0 boolean `exclusiveMinimum`/`exclusiveMaximum` travel with the bound they belong to (AM-10).
- `enum` members and `const` values are compared structurally (AM-13).
- `dependencies` is merged under draft-04 rules (AM-17); `allOf` nested under `not` is merged (AM-18).
- Merging two `items` under OpenAPI 3.0 rules no longer throws; function rules receive the json-crawl context (AM-06).
- Cyclic JavaScript input mixed with `$ref` items no longer throws (AM-07).
- Input is never mutated (AM-14); the audit suite deep-freezes its inputs.
- `resolvePointer` follows intermediate `$ref` nodes and applies the remaining segments, and returns `undefined` for a self-referencing `$ref` (AM-16); `parseRef` honours `basePath` for local refs (AM-22).
- OpenAPI rules cover `callbacks`, `webhooks`, `components.pathItems`, `components.callbacks`, parameter/header `content` and `encoding/*/headers/*/schema` (AM-21).
- `number ∧ integer` is `integer` in nested properties and in type arrays (`["number","null"] ∧ ["integer","null"]` → `["integer","null"]`) (#232).
- Plain-name fragments (`#foo`) resolve `$anchor`, `$dynamicAnchor` and draft-06/07 `$id: "#foo"`; an unknown one is a broken ref instead of the document root, and `#/` is the member `""` of the root (VR-36). A ref -> ref cycle inside `allOf` is reported through `onRefResolveError` instead of vanishing (VR-40).
- A custom `$` that hands a keyword group back to the per-key table no longer reintroduces old defects (VR-39): the per-key fallbacks for `properties`/`patternProperties`/`additionalProperties`, `items`/`additionalItems`/`prefixItems`, `pattern`, `contains` and `if` consult every item of the node (with the call's `matchPatterns`); under draft-04 the boolean `exclusiveMinimum`/`exclusiveMaximum` travels with the bound value the (custom) `minimum`/`maximum` rule selects (exclusive if any item with that value is).
- A custom rule `"/x": { $: jsonSchemaMergeResolver }` without child rules and a direct call of the exported `jsonSchemaMergeResolver` fully merge the children again and report conflicts, as in 0.6.8 (VR-38).
- A bare `$ref` whose pointer passes through an `allOf` member (`#/allOf/0/properties/a`) dangled once that `allOf` was merged (also in 0.6.8); its target is now inlined. An empty or non-string `$ref` inside `allOf` is a broken ref (VR-42).
- Malformed boolean keywords (`uniqueItems: "hi"`, `nullable`, `readOnly`, …), non-schema `items`/`additionalItems`/`prefixItems` values and invalid regular expressions are reported through `onMergeError` (D-6).
- The merge memo of a `createMerger` is keyed by the rules object, so per-call `rules` never return a result merged with other rules (VR-33).

### Security and resource limits

- Prototype safety (VR-20 … VR-23): every write of a user key goes through own-property-safe helpers (`hasOwn`, `getOwn`, `safeSet`, `safeClone`, `safeAssign` in `src/safe.ts`), lookups ignore inherited members. `__proto__`, `constructor` and `prototype` survive as own keys in `properties`, `patternProperties`, `definitions`/`$defs`, `dependencies`, `enum`, `example` and at the top level; a memoized conjunction under the key `__proto__` no longer sets the prototype of the output; `constructor` no longer bypasses `additionalProperties: false`; `resolvePointer` and the resolution index never return `Object.prototype` (refs to inherited members are broken refs).
- ReDoS (VR-02, D-3): user patterns are executed only within `matchPatterns` limits (256 characters for patterns and names by default), never for patterns with nested quantifiers, at most 100 000 name × pattern tests per node; `matchPatterns: false` disables matching. The compiled-pattern cache is an LRU of 1 000 entries (VR-24), the merger memo is weakly keyed.
- `$ref` fan-out (VR-03, D-7): `maxRefExpansion` (default 10 000 inlinings of one target per call) and `expansionBudget` (default 2 000 000 schema nodes copied in by inlining per call; the size of every inlined target counts, so a large target fanned out below the per-target limit is bounded too). The 25-level "billion laughs" document (3.7 KB) gives 2.7 MB of output in ≈ 10 ms instead of a 100 M-node tree; the real-world maximum measured on the GitHub, Stripe, Asana, Kubernetes and Bitbucket specifications is 111 inlinings of one target and 4 777 inlined nodes in total.
- `branchBudget` is one budget per `merge()` call across all nodes, including the `mergeCombinarySibling` distribution and the exported `jsonSchemaMergeResolver` (VR-05).
- Depth (VR-04, VR-06): `maxDepth` (default 2 000) stops merging below that depth (nodes are copied); every walk (`collectItems`, ref resolution, `deepEqual`, `mergeValues`, `canonicalKey`) is iterative, so 20 000 nested `allOf` levels or `$ref` chain steps do not overflow the stack.
- Quadratic merges (VR-07): `enum`, `required` and `dependencies` use structural hash sets, `properties` merging visits per name only the items that can affect it (20 000 enum objects or required names, 10 000 single-property items: milliseconds instead of seconds).
- Rule sets are deep-frozen (also OpenAPI and GraphApi and lazily derived child rules), so `jsonSchemaMergeRules()["/minItems"].$ = …` cannot change other merges (VR-26).

### Added

- Issue model (`docs/NORMALIZATION_DESIGN.md` §3, decisions §9): `MergeOptions.onIssue(issue)` and `issueLevel` (`"error" | "warning"`, default `"warning"`), `mergeWithIssues(value, options) → { result, issues }`, the `MERGE_ISSUES` table and the types `MergeIssue`, `MergeIssueCode`, `MergeIssueSeverity`, `MergeIssueCategory`. 28 codes with two severities: errors for invalid input (malformed values, broken or cyclic `$ref`, cyclic values, invalid patterns) and for contradictions (`unsatisfiable` with a `reason`, `unsatisfiable-combinator`); warnings for external `$ref`s, parts kept unmerged (patterns, `contains`, conditionals, `unevaluated*` items, object shapes, `multipleOf`, legacy tuples, non-JSON `schemaFormat`), limits, removed impossible branches, nodes kept for link validity, copies made instead of links and an overridden OpenAPI 3.0 `nullable`. Outcomes a merge rule defines (last-wins annotations and vendor keys, the numeric format lattice, removed duplicates, rewritten links, identity keywords of inlined targets) are not issues. Each issue carries `path` (output location), `sourcePointer` (input location in `source`), `keyword`, `values`, `ref` and `reason`. `onMergeError` / `onRefResolveError` keep firing for the codes they covered, with the same messages; new codes never reach them. README section "Issues".
- `merger.merge(value, { rules?, source?, onIssue? })`: a per-call issue sink; `merger.needsMerge(value)`: whether merging can produce anything but a plain copy (the fast-path predicate, for consumers that want to skip the call).
- `MergeContext.report(code, values, details?)`, `MergeContext.key` and `MergeContext.forward` for resolvers; `GroupContext.report(message, values, hint?)` takes an issue code hint (without one a custom report is a `merge-conflict`).
- `schemaMergeRulesFor(dialect)` (the schema rules of a JSON Schema draft, a `$schema` URI, OpenAPI 3.0 / 3.1, the AsyncAPI schema or a `schemaFormat`), `jsonSchemaDraftOf(uri)`, and a `dialect` argument for `openApiMergeRules` / `openApiJsonSchemaMergeRules` (OpenAPI 3.1 `jsonSchemaDialect`).

- AsyncAPI 2.x and 3.x (#107, FEATURE_DESIGN §2, decisions Q2-1 … Q2-5): `asyncApiMergeRules("2.x" | "3.0", customRules?)` document rules, auto-detected by `merge` / `selectMergeRules` (`detectAsyncApiVersion`); payloads and headers are merged with the rules of their `schemaFormat` (`asyncApiSchemaMergeRules(schemaFormat, customRules?)`, `asyncApiSchemaDialect`: the AsyncAPI schema = draft-07 + `discriminator`, JSON Schema drafts, OpenAPI 3.0 / 3.1 schemas; Avro, Protobuf, RAML and unknown formats untouched); 3.x Multi Format Schema Objects at payload / headers / `components.schemas`; a `$ref` inside `allOf` to a 3.x wrapper is unwrapped for AsyncAPI / JSON Schema formats and kept (`{ $ref }` part + `onMergeError`) for any other format (`unwrapSchemaFormat`); the schema fields of the `ws`, `http`, `kafka`, `mqtt` and `anypointmq` bindings (`asyncApiBindingSchemaFields`). README section "AsyncAPI".
- `MergeOptions.refAnnotations: "merge" | "omit" | string[]` (#222, FEATURE_DESIGN §1, decisions Q1-1 … Q1-4), default `"merge"` (output unchanged): `"omit"` drops `title`, `description` and `$comment` (`DEFAULT_OMITTED_ANNOTATIONS`) that a merged node gets only through a `$ref`, a list drops the listed keys (`"x-*"` is a prefix); the node's own values always stay, a reference resolution (a copy made by the link rules, a `$ref` branch distributed by `mergeCombinarySibling`) keeps the target's annotations. A branch of a `oneOf`/`anyOf` product keeps the annotations of its `$ref` components too (D-26), combined by the keyword's merge rule: `allOf: [{ oneOf: [{ $ref: Cat }] }, { oneOf: [{ $ref: Indoor }] }]` → one branch titled `Indoor` (default last-wins), `Cat` with a custom first-wins `/title` rule; also when `mergeCombinarySibling` distributes siblings into such branches (an earlier 1.0.0 draft dropped them there). `{ allOf: [{ $ref: Base }, { properties: … }] }` with `Base.title: "Base"` → no `title`. Rule-level control (`inherit: false`) is planned for 1.1.0.
- `MergeOptions.dedupeAnyOf`, `dedupeFragments`, `dedupeCombinaryGroups`, `dropFalseBranches` (all default `true`, see the output-contract changes above) and `MergeOptions.simplify: boolean | { enumByType?, contradictions?, redundantBounds?, containsToMinItems? }` (default off, FEATURE_DESIGN decision Q3-2): exact, type-guarded, form-changing rules for merged nodes — `enum`/`const` filtered by `type` (`{ type: string, enum: [a, 1] }` → `enum: [a]`, empty → `false`), typed bound contradictions → `false` (`{ type: number, minimum: 15 } ∧ { maximum: 10 }`), the impossible kind removed from a type list (`{ type: [number, string], minimum: 15, maximum: 10 }` → `{ type: string }`), typed required + impossible property → `false`, `contains: false` with an array-only type → `false`, `contains: true`/`{}` → `minItems ≥ 1` (draft-06/07 rule sets only), redundant inclusive/exclusive bounds → the tighter one (draft-06+). Never: `oneOf` dedupe, untyped contradiction collapse, dropping `contains: true` or an `if` without `then`/`else`. The schema rule sets carry a `draft` marker (`MergeRule.draft`) the rules read.
- Property-based equivalence test (dev only, FEATURE_DESIGN §4, decisions Q4-1 … Q4-4): `test/fuzz` generates random `allOf` pairs/triples per profile (draft-07, 2020-12) with fast-check, randomizes `mergeCombinarySibling`, `mergeRefSibling`, `refAnnotations`, the four safe simplifications and `simplify`, and checks merged ≡ original with `@cfworker/json-schema` (ajv as a logged second opinion), idempotence and serializability; a committed corpus (real-world cases of other libraries, probes, earlier fuzz runs) is replayed. `npm run test:fuzz`; `FUZZ_SEED` / `FUZZ_RUNS` / `FUZZ_PATH` for local runs. Dev dependencies `fast-check` and `@cfworker/json-schema`.
- `createMerger(options) → { merge, hook }`: a reusable merger holding the resolution index, the merge memo and the sibling-spread cache for its lifetime (for merge-on-every-node consumers).
- `MergeOptions.unsatisfiable: "false" | "not-empty"` (default `"false"`) and `MergeOptions.branchBudget` (default 1024 per `merge()` call): a `oneOf`/`anyOf` cartesian product above the remaining budget leaves the node unchanged and calls `onMergeError`.
- `MergeOptions.matchPatterns: boolean | { maxPatternLength?, maxNameLength? }` (default `true` with 256/256), `maxRefExpansion` (default 10 000), `expansionBudget` (default 2 000 000), `maxDepth` (default 2 000) and `freezeOutput` (default `false`).
- `JsonSchemaVersion` values `"draft-07"` and `"2020-12"` (`prefixItems`, `dependentRequired`, `dependentSchemas`, `unevaluatedProperties`, `unevaluatedItems`, `minContains`/`maxContains`, `if`/`then`/`else`, `$anchor`, …); the default stays `"draft-06"`; draft-06, draft-07 and 2020-12 share one keyword table, OpenAPI 3.1 schemas use the 2020-12 keywords.
- `MergeRule.group`: built-in keyword rules are tagged with the keyword group that owns them; a custom `$` on a grouped key hands the whole group back to the per-key table.
- Vendor / unknown keyword rules (D-19): prefix rules (json-crawl 1.0, `"/<prefix>*"`) in custom rules, e.g. `jsonSchemaMergeRules("draft-07", { "/x-*": rule })`, apply at every schema depth with the json-crawl precedence exact key > longest prefix > `/*` > `"/?"`; a custom `"/?"` rule overrides the last-wins default for every unknown key (documented in the README, "Vendor and unknown keywords").
- `openApiMergeRules(version, customRules?)` and `openApiJsonSchemaMergeRules(version, customRules?)` take schema-level custom rules (applied at every schema location of the document), memoized per `(version, customRules)`; `createGraphapiMergeRules(customRules?)` does the same for GraphApi (`createGraphapiMergeRules()` is `graphapiMergeRules`). Custom rule objects are only referenced, never frozen (`freezeRules` no longer enters already frozen rule sets).
- `mergeOpenApiFormat` resolver (the format rule of the OpenAPI rule sets, with the numeric lattice; `"/format": { $: mergeOpenApiFormat, group: "string" }` enables it elsewhere); `mergeFormat` is strict (D-14). `mergeFormats(values, report?, lattice = false)` got the `lattice` flag.
- `MergeRule.tuple: "items" | "prefixItems"`: the tuple keyword of a schema rule set, set by `jsonSchemaMergeRules` (D-18); hand-written rule trees without it keep reading both forms. `knownKeyRule(rules, key, path, value)` (the rule a rule set defines for a key, without the `"/?"` fallback) is exported next to `findKeyRule`; `asFragments(list, { value })` lets a per-key resolver write its key and fragments at once.
- Exported for advanced use: `createResolutionIndex(source)` (with `pointerOf`, anchors), `intersect`, `findKeyRule`, `resolveMergeSettings`, `UNCHANGED`, `keywordGroups` and the group objects (`typeGroup`, `enumConstGroup`, `numericBoundsGroup`, `stringGroup`, `objectShapeGroup`, `arrayShapeGroup`, `dependenciesGroup`, `conditionalGroup`), `freezeRules`, the resolvers `mergeFormat`, `mergeSchemas`, `mergeConjunction`, `conjunctPatterns`, `containsMergeResolver`, `minContainsMergeResolver`, `maxContainsMergeResolver`, `prefixItemsMergeResolver`, `patternPropertiesMergeResolver`, `conditionalMergeResolver`, `draft04ExclusiveMinimum`, `draft04ExclusiveMaximum`, `intersectTypes`, `and`, and the utilities `deepEqual`, `canonicalKey`, `ValueSet`, `uniqueConcat`, `lcmOf`, `isValidMultipleOf`, `MAX_MULTIPLIER`, `countCombinations`, `compilePattern`, `testPattern`, `matchPattern`, `isMatchablePattern`, `hasNestedQuantifier`, `patternLimits`, `regexpCacheSize`, `REGEXP_CACHE_SIZE`, `DEFAULT_PATTERN_LIMITS`, `DEFAULT_BRANCH_BUDGET`, `isPlainObject`, `isEmptyObject`, `isAnchorPointer`, and the fragments protocol of per-key resolvers (`FRAGMENTS`, `asFragments`, `isFragments`, `fragmentsOf`: a resolver result that is added to the node's `allOf` instead of the key). `MapArray` stays exported for compatibility (unused by the engine).

### Performance

- Fast path (`docs/NORMALIZATION_DESIGN.md` §3.6): a subtree without `allOf` and without the forms the options rewrite is scanned and copied in one iterative pass, without clone frames, rule resolution or link checks; `ownersOf` (the D-22 link check) only considers nodes the merge rewrites and only runs in whole-document mode; a repeated fragment-mode call is answered from a per-merger result cache; issue source pointers are computed only when a sink listens. Same output on every test resource, the fuzz corpus and the api-smart-diff bench fixtures. Measured against the previous 1.0.0 sources (esbuild bundles, Node, min of 15): GraphApi github 46 → 17 ms, OpenAPI github (14 MB) 232 → 120 ms, 200 per-node merges with one merger 6.5 → 3.6 ms, 200 warm repeated calls 1.2 → 0.04 ms, oas-petstore 0.54 → 0.24 ms.

- No `JSON.stringify` fingerprints, no pointer strings and no exit hooks in the hot path; results are memoized per item-identity tuple and repeated usages are written with `done`; rules are memoized and frozen per `(draft, custom)` identity. Deep documents are linear instead of quadratic (1 000 nested levels: 1.7 s → 0.03 s), 4 000 usages of one `$ref` ~10× faster, 1 000 usages of a 1 000-property target ~20× faster; see `docs/DESIGN_PROPOSALS.md` §9 for the table against the §6 targets and `docs/VERIFICATION.md` §9 for the measurements after the verification fixes (wide 5 000: 27 ms, deep 1 000: 28 ms, plain chain of 20 000 levels: 0.1 s, 4 000 refs: 42 ms, 1 000 × 1 000: 0.3 s, ring of 200: 78 ms).

### Internal

- No circular module dependencies (the build warned about three, all introduced by the redesign): `mergeFormats` lives in `src/groups/format.ts` (still exported from the string group), `jsonSchemaMergeResolver` in `src/resolvers/conjunction.ts`, which reaches `createMerger` and the default rules through the late-bound leaf `src/engine.ts`; `src/intersect.ts` no longer imports the merger or the rules. Public exports are unchanged.
- `src/normalize.ts` is replaced by the resolution index (`src/resolve.ts`), the intersection engine (`src/intersect.ts`) and the keyword groups (`src/groups/*`). `ajv` was added to the devDependencies as the semantic oracle of the audit suite. `rollup.config.js` reads `package.json` through `createRequire` (an ESM JSON import needs an import attribute on current Node versions).
