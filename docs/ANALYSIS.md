### B.2 Complexity and hotspots (from the code)

1. **One `syncClone` pass, one hook invocation per node** (merge.ts:27). The hook runs for every value including primitives; for every object node it allocates the `mergeError`/`exitHook` closures, destructures `{ allOf, ...sibling }` (an object spread per node, merge.ts:91) and checks `isAllOfMergeRule`. This is the fixed ≈3× overhead over a bare clone visible in the "wide without allOf" row.
2. **`buildPointer(path)` in every `exitHook`** (merge.ts:64) builds a string from the full path with `encodeURIComponent` and two regex replaces per segment, only to look it up in `nodeToDelete`, which is almost always empty. json-crawl also copies the path array per node (`[...o.path, r]`). Both are O(depth) per node, giving **O(n·depth)** and the quadratic deep-nesting curve above (1 000 levels: 1.7 s vs 50 ms for the clone). A cheap fix is to skip `buildPointer` when `nodeToDelete.size === 0`, or to key `nodeToDelete` by parent array identity.
3. **Lazy rule construction allocates a fresh rules object per node.** `jsonSchemaMergeRules()` builds a ≈50-key object; the rule tree references it through thunks (`"/*": () => jsonSchemaMergeRules(draft, customRules)`, rules/jsonschema.ts:25-85), so json-crawl's `getNodeRules` evaluates a thunk for every schema node, and `jsonSchemaMergeResolver` evaluates it again for every merged key (`rule()` at resolvers/jsonschema.ts:40). With custom rules the `...customRules` spread is repeated each time. Memoizing the per-draft rule object (it is immutable) removes most of this allocation.
4. **`normalizeAllOfItems` per allOf containing a `$ref`**: `JSON.stringify(allOfItems)` of the whole item list (normalize.ts:18) plus a linear `allOfRefs.find` over every previously seen ref-bearing allOf (normalize.ts:34). `allOfRefs` is never pruned for the lifetime of the hook, so a document with R such nodes costs **O(R²)** comparisons of stringified data — the superlinear "many refs" curve (4 000 refs: 349 ms, 89 µs each vs 42 µs at 100). Indexing by `normalized` ref in a `Map` and fingerprinting the items by identity would make it O(R).
5. **`resolvePointer` is O(pointer length)** per `$ref` and negligible (9-segment pointers cost the same as 2-segment). The real cost of a `$ref` is that the resolved target is returned by reference and then **re-crawled and re-cloned by `syncClone` at every usage** (O(usages × target size)): 1 000 usages of a 1 000-property target cost 6 s. There is no cache of "merged result for target X", so the same subtree is normalized and merged again at each site; cyclic targets are protected only by json-crawl's instance map, which is also why output usages share nodes (AM-27).
6. **`getPropertiesForMerge`** is O(items² × properties × patterns) and compiles `new RegExp(pattern)` for every (property, pattern) pair (resolvers/properties.ts:21) with no regex cache. `getPatternPropertiesForMerge` is O(items² × patterns).
7. **`jsonSchemaMergeResolver`** does `getAllOfItemsMap` (one pass), then per key: rule lookup, `{ ...ctx, allOfItems: args }` spread (resolvers/jsonschema.ts:47) and the resolver. `mergeObjects`/`mergeValues` deep-copy `definitions`, `examples`, `xml`, `discriminator` recursively (O(size), one spread per level). `mergeEnum` stringifies and parses every enum member; `equal` stringifies the const.
8. **`mergeArray` / `findCombinations`** for `oneOf × anyOf` across allOf items is a cartesian product: k combinaries with m branches each produce m^k branches, each a new `{ allOf: [...] }` node that is then merged. Pathological but legal inputs (several `oneOf` in one allOf) explode exponentially.
9. **Merging on every node** (api-smart-diff style, `merge(node, { source: root })`): each call re-runs the hook over the whole subtree, so the total is Σ|subtree| = **O(n·depth)**; the measured 3–5× overhead for depth 3–6 trees grows linearly with depth. Because results are not cached between calls, every nested allOf is normalized and merged `depth` times. A single top-level `merge` followed by pointer look-ups into the merged document is strictly cheaper; alternatively memoize merged results per source node instance inside one `allOfResolverHook` and reuse the hook across calls.
10. No `JSON.stringify`-style hashing is used except the two places above (cycle fingerprint in `normalize.ts`, `isEqual` for const/enum); there is no memoization anywhere.

Complexity summary: wide documents are O(n); depth adds an O(n·depth) factor (quadratic for a chain); `$ref` sites add O(R²) plus O(usages × target size); combinary products are exponential in the number of combinaries per allOf.

## C. Fork comparison: `@netcracker/qubership-apihub-api-unifier` 2.9.3

### C.1 How the pipeline evolved

allof-merge is a single `syncClone` pass with one hook (`allOfResolverHook`): `$ref`s are resolved lazily inside the allOf merge (`normalizeAllOfItems`), nested allOf is flattened, cycle detection fingerprints the item list with `JSON.stringify`, impossible `oneOf`/`anyOf` branches are deleted through the `nodeToDelete` map in an exit hook, and `mergeRefSibling`/`mergeCombinarySibling` are opt-in rewrites. Rules are picked by `selectMergeRules` (OpenAPI `/3.+/`, `graphapi`, otherwise draft-06).

The unifier turns this into a multi-phase `normalize()` (`src/normalize.ts`): `preValidate → defineOriginsAndResolveRef → validate → merge → mergeTraits → unify → cleanUpSynthetic → removeOasExtensions → hash`, with a `denormalize()` that reverses the reversible phases (`deHash → deCleanUpSynthetic → deUnify → deDefineOrigins`). `$ref` resolution became its own clone pass (`define-origins-and-resolve-ref.ts`, 661 lines, `references/ref-resolver.ts`): every `$ref` is inlined before merging, wrapped as `{ allOf: [syntheticTitle?, target, siblings?] }`, sibling handling is spec-gated (allowed for draft-07/OAS 3.1, reported as `richRefObjectNotAllowed` otherwise), OAS Reference Objects may only override `description`/`summary`, broken refs are reported with an `errorType` and left as `{ $ref }`. Cycles are handled by `cycle-jso.ts` (one output instance per input instance, in-progress placeholders) plus an evaluation cache keyed by item-list identity (`cache.ts`), which also makes a self-referential allOf resolve to the object being built. `merge.ts` (158 lines) no longer resolves refs: a leftover `$ref` yields `mergeWithBrokenRef` and the node is returned unchanged; boolean items are converted by `unifyBooleanSchemas`; an `undefined` merge result writes the original node back. `nodeToDelete`, `findNodeToDelete`, `mergeRefSibling` and `mergeCombinarySibling` are gone; `liftCombiners` (`lift-combiners.ts`, opt-in) pushes siblings into `oneOf`/`anyOf` branches (and takes the cartesian product when both are present) without a sibling whitelist.

### C.2 Resolvers and rules

The resolver signature changed to `(args: ValueWithOrigins<T>[], ctx) => ValueWithOrigins<T> | undefined`, so every resolver threads origin metadata. Behavioural differences: `type` conflicts yield synthetic `nothing` (and `any` expands to all types) instead of `undefined`; `enum`/`const` use `fast-equals.deepEqual`, no sorting; `required` keeps insertion order; `pattern` deduplicates and sorts but keeps the lookahead construction; `multipleOf` is identical; `examples`/`example` and `discriminator` are demoted to `last`; `nullable` → `or`; `additionalItems` builds fresh wrappers; `properties × patternProperties` collects every matching pattern schema into the property's allOf and adds `additionalProperties` when present (but forces `false` when no pattern matches, even without `additionalProperties`), while the `patternProperties`-vs-`additionalProperties:false` filtering was dropped; rule lookup uses json-crawl's `getNodeRules` and throws `ruleNotFound` for an unknown duplicated key unless `validate` removed it first (`x-*` get `last` through a prefix rule).

Rules became `NormalizationRule` objects carrying `merge`, `validate`, `unify`, `hashStrategy`, `deprecation`, `referenceHandler`, … with keyword constants per spec. `RULES` is built once per spec (`json-schema-04/06/07`, `openapi-3.0/3.1`, `graphapi`, `asyncapi-3`, `ddlapi-1.0`); `resolveSpec` throws for unsupported versions (OAS 3.2, Swagger 2) where allof-merge silently falls back. JSON Schema rules add `contentMediaType`, type-restricted `propertyNames`, a `'/defs'` entry that looks like a typo for `$defs`, boolean-vs-numeric exclusive bounds by version; OpenAPI rules cover the whole document (info, servers, security, paths incl. callbacks, `components.*` incl. `pathItems`, `links`, `examples`, `securitySchemes`) with per-location validation, defaults and hashing metadata; OAS 3.0 forbids `additionalItems`/`patternProperties`/`null` type; GraphApi rules were rewritten for `@netcracker/qubership-apihub-graphapi` and have no merge rules; AsyncAPI 3 (schemaFormat dispatch, `traits` merge) and DDL API (Postgres dialect) are new.

| Origins (`origins.ts`, 322 lines + threading in every resolver) | Symbol-keyed `obj[originsFlag] = { key: ChainItem[] }` on every output node, pointing back to the source locations that produced each value; used by diff/UI tooling. | One extra record per node, doubled code paths, helpers flagged "doesn't support ORIGINS"; output decorated with symbols. |

Totals: 1 044 → 10 715 lines; runtime deps `json-crawl` → `@netcracker/qubership-apihub-json-crawl`, `-graphapi`, `-ddlapi` (all pinned to the `dev` dist-tag on GitHub Packages, so an `.npmrc` token is required), `fast-equals`, `flatted`, `object-hash`, plus a runtime `yaml` import listed only in devDependencies. Public API: `merge` is **not exported**; the entry point is `normalize(value, options)` / `denormalize`; `rules` and `selectMergeRules` are gone (no custom rules), `mergeRefSibling` is always-on and spec-gated, `mergeCombinarySibling` became `liftCombiners`, `onRefResolveError` gained an `errorType`, `source` and `onMergeError` survive. Output is cyclic (refs inlined as shared instances) and symbol-decorated; `JSON.stringify` throws without `serialize()`/`denormalize`.

### C.4 Which audit findings the fork fixes

Fixed: AM-01 (synthetic `nothing`, original node on `undefined`), AM-04 (mostly), AM-05, AM-06, AM-07, AM-08 (by removing branch deletion), AM-09 (partly), AM-11 (as `or`), AM-13, AM-14, AM-15, AM-16 (rewrite), AM-21. Not fixed: AM-02 (`integer ⊂ number`), AM-03 (pattern lookahead), AM-10 (boolean exclusive bounds), AM-12 (`contains`), AM-17 (draft-04 `dependencies`), AM-19 (single `additionalItems`), AM-20 (2020-12), AM-25. New in the fork: `$defs` registered as `/defs`, `patternProperties` filtering lost, over-restrictive `false` for properties matching no pattern, `discriminator`/`examples` last-wins, throwing on OAS 3.2 / Swagger 2.

### C.5 Porting verdict (pros / cons per change)

| Change | Port? | Pros | Cons |
| --- | --- | --- | --- |
| Synthetic `nothing` for type conflicts (AM-01/02 area) | **Yes, adapted**: emit `false` (or `{ not: {} }`) instead of dropping the key, never return `undefined` for a node; add `integer ⊂ number`. | Restores the "does not validate more" guarantee; small change in `mergeTypes` + `jsonSchemaMergeResolver` + hook. | Changes output for consumers that relied on the property disappearing (api-smart-diff should treat `false` as "removed"). |

| Fresh wrappers in `additionalItemsMergeResolver` (AM-14) | **Yes** | Removes input mutation. | None. |
| Leave node unchanged on broken ref (AM-15), `getNodeRules` for rule lookup (AM-06) | **Yes for the two bug fixes**, no for the full two-pass architecture. | Fixes a crash and structure corruption with local changes. | A full pre-resolution pass loses allof-merge's "merge a fragment with `source`" use-case and inlines every ref (bigger output). |
| Instance-identity evaluation cache (`cache.ts`) | **Yes, simplified**: memoize the merged result per source allOf array identity within one hook; also fixes AM-07 by replacing the `JSON.stringify` fingerprint. | O(R) instead of O(R²), removes the stringify, makes repeated `$ref` usages cheap, cycle-safe. | Shared output instances between usages (already the case, AM-27). |
| Remove branch deletion (`nodeToDelete`) in favour of impossible-branch schemas (AM-08; since the D-12 decisions of 2026-11-17 the merge removes impossible branches again after the subtree is merged, option `dropFalseBranches`, default true — exact, no `null` holes, all-impossible → `false`) | **Yes** | Removes the only exit-hook work (`buildPointer` per node → also fixes the O(depth²) hotspot), no `null` entries, simpler. | Impossible branches stay visible as `false` (consumers wanting pruning can filter `false`). |
| `liftCombiners` replacing `mergeCombinarySibling` | **No** | — | Drops the sibling whitelist (`discriminator`, `definitions` would be pushed into branches) and risks cartesian explosion; the current option is fine. |
| Spec-gated always-on `$ref` sibling merging | **No** (keep the option) | Spec-correct for draft-07/3.1. | Breaks the opt-in contract and drops siblings for draft-04/06 users. |
| Origins, defaults, validation, hashing, deprecated items, synthetic type cleanup, AsyncAPI/DDL, denormalize | **No** | Valuable for an API hub product. | 10× code, three private-registry dependencies, symbol-decorated cyclic output, removal of `merge`/`rules`; orthogonal to allOf merging and to api-smart-diff's needs. |
| `resolveSpec` throwing on unknown versions | **No** | Explicit. | Regression for OAS 3.2 / Swagger 2 users who get a sane fallback today. |
| Stop sorting `enum`/`required`, dedupe patterns (AM-26) | **Yes** | Deterministic, order-preserving output. | Cosmetic diff in expected outputs of existing tests. |

Fixes the fork does not provide and allof-merge should do itself: AM-03 (`^(?=[\s\S]*?(?:p))…` pattern intersection), AM-10 (merge boolean exclusive flags together with the bound), AM-12 (`contains` → keep both via `allOf`), AM-17 (`dependencies` in draft-04), AM-19 (run `additionalItemsMergeResolver` when any item has `items`), AM-20 (2020-12 keyword rules), AM-23 (revert or fix the uncommitted `normalize.ts` change before publishing), and the performance items B.2.2–B.2.4 (skip `buildPointer` when nothing is scheduled for deletion, memoize the per-draft rules object, index `allOfRefs` by ref).
