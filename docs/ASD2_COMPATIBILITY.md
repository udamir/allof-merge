# allof-merge 1.0.0 × api-smart-diff 2.0 — compatibility report (2026-11-17)

## 1. Verdict

Compatible, with three small adaptations needed in api-smart-diff (asd) before release. Dropping the new allof-merge build (`dist/` + `package.json` of this worktree) and json-crawl 0.6.0 (lazy-path build) into asd 2.0 changes nothing that asd's own checks measure. `tsc --noEmit` is clean, `bun test` gives 5 877 pass / 0 fail (the same as the baseline), and the compat report is byte-identical (100 % detected / classified / annotated in every family). A full-output differential over all 5 212 compat variants and 36 benchmark fixture pairs (every diff with type / action / path / scope / description, plus the serialized merged document) also shows 0 differences. Those suites do not exercise most of the new contract, so targeted probes were run as well. They found three behaviour changes that asd must adapt to (F-1 spurious branch-removal diffs, F-2 lost OpenAPI format lattice, F-12 performance), one asd bug that the new resolver exposes (F-7), one minor allof-merge defect (F-10, idempotence of the branch simplifications), an allof-merge performance regression against the 2026-11-15 draft that asd measured its gates with (F-11), and four classification questions that need a user decision (§7).

Update 2026-11-17: the user answered the open decisions (§9). They reverse the §6.1 adaptation (F-1), replace §6.2 (F-2) by the delegation of the merge rules to allof-merge, turn F-3 / F-4 / F-5 into issues of a new structured issue model, and move F-12 into an allof-merge fast path. The design for these changes is `docs/NORMALIZATION_DESIGN.md`; the finding rows below carry the updated required change.

Counts: 15 findings. 8 are category (a), intended 1.0.0 contract changes (2 of them need an asd code change, 2 need a decision, 2 are improvements, 2 need only docs). 2 are category (b), in allof-merge (1 correctness defect with low impact, 1 performance). 1 is category (c), json-crawl (no impact). 1 is category (d), environment. 3 are asd-side items (an exposed asd bug, a performance mitigation, a bundle-size update).

## 2. Setup and method

- Baseline copy `/tmp/asd2-base`: `cp -R` of `api-smart-diff-redesign`, unchanged. Its `node_modules/allof-merge` is the 2026-11-15 draft build (banner v0.6.8, 69 exports) and `node_modules/json-crawl` is 0.6.0 without lazy paths.
- Swapped copy `/tmp/asd2-compat`: the same tree with `node_modules/allof-merge/{dist,package.json}` replaced by this worktree's build (banner v1.0.0, 122 exports, none removed) and `node_modules/json-crawl/{dist,package.json}` replaced by `allof-merge-redesign/node_modules/json-crawl` (lazy paths, `path.d.ts`, named re-exports from `rules`). No nested copies exist: the only packages in asd's `node_modules` that name `allof-merge` or `json-crawl` are those two, `gqlapi` 0.5.1 has no dependencies, and api-ref-bundler is not installed. The allof-merge bundles inline json-crawl, so at runtime asd's own json-crawl copy only serves asd's direct imports.
- Instrumented copy `/tmp/asd2-shadow` (swapped copy plus a wrapper in `getSessionMerger` and in the GraphApi merge). Every merge call runs on both the old and the new engine, with the old rule sets mapped by draft, and the outputs are compared as canonical JSON with cycle markers. An option deep-freezes every new output (`freezeOutput: true`) to detect any mutation of shared instances by asd.
- Adapted copy `/tmp/asd2-adapt` (swapped copy plus the adaptations of §6), to verify them.
- Benchmark: the main worktree's `bench/` was copied to `/tmp/asd-bench` (without `work/`, so no TBAPI). The `asd-2.0.0` bundle was built once per copy (`ASD_NEW=<copy> node scripts/build.js --only asd-2.0.0`), and `scripts/bench.js` (20 warm-ups, 11 runs, min) was run twice per build on 10 fixtures, with `BENCH_RESULTS` redirected to `/tmp`. The real repositories were only read. Scratch scripts are in `/tmp/asdcmp/` (`differential.ts`, `cmp.ts`, `probes.ts`, `asym.ts`, `p15.ts`, `micro*.mjs`, `repro.ts`, `shadow.ts` in `/tmp/asd2-shadow/temp`).
- The oracle test (`test/compat/core/oracle.test.ts`) and X-WEAK-003 look for `../api-smart-diff/bench` and skip outside the repository directory. A symlink `/tmp/api-smart-diff` → the main worktree makes them run (finding F-15).

### 5.1 Reproducer F-10 (against `src`)

```ts
import { merge } from "./src"
const s = { type: "string" }, n = { type: "number" }
merge({ anyOf: [s, s, n] })                                // { anyOf: [s, n] }            deduped
merge({ allOf: [{ anyOf: [s, s, n] }, { minLength: 1 }] }) // { minLength: 1, anyOf: [s, n] }  deduped
merge({ allOf: [{ anyOf: [s, s, n] }] })                   // { anyOf: [s, s, n] }         NOT deduped
merge({ allOf: [{ anyOf: [s, s, n] }, {}] })               // { anyOf: [s, s, n] }         NOT deduped
```

### 5.2 Contract points checked without impact on asd

`$ref` siblings in every draft (D-24) match asd POLICY-25 ("apply them", probe P4: `allOf: [{ $ref: Name, maxLength: 3 }, { minLength: 1 }]` → "breaking add maxLength", in both builds). Link rewriting (D-22 / D-23 / D-27) applies in asd only where the merged node is the document root. It changed the merged root of the JSON Schema probes (`#/allOf/0/properties/a` → `#/properties/a`), but asd's diffs were identical, because asd resolves against the transformed root. With F-1 applied no branch index shifts. Fragment mode leaves `$ref`s as they are (D-25), and that is how asd calls it for every non-root node. `refAnnotations` defaults to `"merge"`, so annotations are unchanged. Limits: `branchBudget`, `maxRefExpansion` and `expansionBudget` are per `merge()` call, and asd calls per node, so each node gets the full budget. `maxDepth` 2 000 counts from the merged node: allOf chains of 500 / 2 500 levels give 1 diff in both builds (0.46 s vs 1.16 s at 2 500 levels), and asd merges deeper nested `allOf`s when its walk reaches them. Malformed values are now reported instead of thrown, and asd passes no `onMergeError`: probes `required: true` and a non-array `allOf` give the same diffs in both builds. The memo is keyed by rules, and asd's key `ruleSetId|…` already includes the rules identity. `integer ∧ number`, first-seen `enum` order and pattern conjunction give the same diffs in both builds. No asd code reads allof-merge error messages.

## 6. Adaptations for asd (verified in `/tmp/asd2-adapt`)

### 6.1 Keep combinator branches as written (F-1)

Rejected by decision C (§9): do not apply this adaptation. Kept here as the record of what was verified.

`src/jsonSchema/jsonSchema.transform.ts`:

```ts
// keep combinator branches as written (no dropped impossible / duplicate branches): the other side may be compared
// unmerged, and a branch index shift would read as a removed branch
const SHAPE_PRESERVING = { dropFalseBranches: false, dedupeAnyOf: false } as const
…
merger = createMerger({ source: root, rules, mergeCombinarySibling, mergeRefSibling, ...SHAPE_PRESERVING })
```

The same applies to the source-less merger in `jsonSchemaMergeAllOf` (no `ctx`) and to the `merge(...)` fallback in `graphApiMergeAllOf`. These are constants, so the merger cache key needs no change. If asd ever exposes these options, add them to `mergerKey`, as the allof-merge CHANGELOG notes. `dedupeFragments` and `dedupeCombinaryGroups` can stay on: they change only the merged node itself, which both sides get in the same form.

### 6.2 OpenAPI merge rules (F-2, Q1)

Superseded by decision A (§9): asd uses allof-merge's rule set of each dialect (option (b) below, through `schemaMergeRulesFor`), not the lattice-only variant.

Add `mergeRules?: MergeRules` to `JsonSchemaRulesOptions` (`src/jsonSchema/jsonSchema.types.ts`), pass it in `jsonSchemaRules` as `jsonSchemaMergeAllOf(version, mergeRules, normalize)` (`src/jsonSchema/jsonSchema.rules.ts`), and set it in `openApiSchemaRules` (`src/openapi/openapi3.schema.ts`). import { jsonSchemaMergeRules, mergeOpenApiFormat, openApiJsonSchemaMergeRules } from "allof-merge"
```ts
// Q1 (a): lattice only, nullable stays the JSON Schema AND (today's asd behaviour)
const OAS_FORMAT = { "/format": { $: mergeOpenApiFormat, group: "string" } }   // module constant: rules are memoized per identity

```

## 7. Open decisions (need the user)

Answered on 2026-11-17, see §9. The text below is the question as it was asked.

1. **OpenAPI 3.0 `nullable` through `allOf`.** Before `{ type: string, nullable: true }`; after `{ allOf: [{ $ref: "#/components/schemas/Base" }], nullable: true }` with `Base = { type: string }`. Today asd reports no change: the merge keeps `nullable: true`, because asd merges OpenAPI schemas with JSON Schema rules. allof-merge's OpenAPI rules read the 3.0.3 wording (a typed item without `nullable: true` forbids `null`), so with them asd would report "[Removed] nullable": breaking in a request body, non-breaking in a response. The same applies to `allOf: [{ type: string, nullable: true }, { type: string }]`. Options: (a) keep today's reading, with the lattice-only rules of §6.2 (recommended: the `allOf: [$ref] + nullable` idiom is common in real specifications and authors mean "nullable"); (b) follow 3.0.3 strictly with `openApiJsonSchemaMergeRules`. Corpus impact of either option: none. Refs: allof-merge D-1, D-13, VR-13; asd POLICY-25, ISSUE-71.
2. **Two different `format`s combined by `allOf` (and other parts the merge cannot combine).** Before `{ type: string, format: date }`; after `{ allOf: [{ type: string, format: date-time }, { format: date }] }`. The previous allof-merge kept the last format, so asd reported no change. allof-merge 1.0.0 keeps both as `allOf` parts, and asd now reports "[Removed] type `string`" (non-breaking), "[Removed] format `date`" (non-breaking) and "[Added] `allOf`" (unclassified). Options: (a) asd compares the kept parts as extra constraints and reports "[Added] format `date-time`", breaking in a request and non-breaking in a response (new asd ISSUE, which also fixes the branch-budget and other kept-part cases of F-5); (b) treat two different formats as no valid value (`false`, as with `type: string ∧ type: number`), breaking per POLICY-40; (c) asd restores "last format wins" with a custom `/format` rule (no change reported, the conflict stays hidden); (d) accept the current output. Recommended: (a), with (c) as an interim. Refs: allof-merge D-2, D-14; asd POLICY-41, POLICY-40.
3. **Removing a `oneOf` / `anyOf` branch that no value can match, or a duplicate `anyOf` branch.** Before `{ oneOf: [{ allOf: [{ type: string }, { type: number }] }, { type: number }] }`; after `{ oneOf: [{ type: number }] }`. Similarly, before `{ anyOf: [string, string, number] }` and after `{ anyOf: [string, number] }`. Both pairs accept exactly the same values. Today asd reports "[Removed] oneOf schema" / "[Removed] anyOf schema" as breaking, in both allof-merge builds and independently of §6.1. Options: (a) no change; (b) one annotation, "[Replaced] … with an equivalent schema"; (c) keep reporting a removal. Recommended: (a) or (b). The ajv oracle would call the pair equal. Refs: allof-merge `dropFalseBranches` / `dedupeAnyOf` (FEATURE_DESIGN Q3-1); asd POLICY-40.
4. **An array-valued `items` next to `prefixItems` in a 2020-12 document.** Before `{ prefixItems: [{ type: string }] }`; after `{ allOf: [{ prefixItems: [{ type: string }] }, { items: [{ minLength: 1 }, { type: number }] }] }`, both declaring 2020-12. The previous allof-merge merged the two as one tuple, so asd reported "[Added] minLength `1`" at item 0 and "[Added] array item 1" (breaking). allof-merge 1.0.0 keeps the array `items` as a separate part, because it is not a tuple keyword in 2020-12, and asd now reports "[Removed] tuple item schemas" and "[Added] `allOf`" (unclassified). Options: (a) asd reads an array `items` as `prefixItems` before merging in 2020-12 documents as well (extends POLICY-28 (b), which today applies only to documents that declare an earlier draft); (b) handle it through the kept-parts comparison of Q2 (a); (c) accept. Refs: allof-merge D-18; asd POLICY-28, ISSUE-138.
5. (Optional) **Surface merge problems.** Input `{ allOf: [{ required: true }, { type: object }] }`, or a branch product over the budget. allof-merge now reports these through `onMergeError` instead of throwing or silently dropping them. asd passes no handler, so nothing is reported today. Option: forward them to asd's `onError` option as warnings (proposed) or keep them silent.
